# dsh-paranim（他化自在天）

DeepSeek Harness 的 **多智能体小镇沙盒** 插件：侧边栏里有一座可编辑、可存档、可回放的小镇，
里面的居民各自由一门 LLM 驱动、自己过日子；玩家可以随时步进时间、改一盏路灯的状态、
或者给某个居民下一条指令。

出厂自带一个**复刻斯坦福 Smallville** 的默认沙盒镜像（素材见 `assets/README.md` 的出处与许可）。

---

## 它是什么（与不是什么）

- **是**：一个宿主级的沙盒运行器。世界状态、运行态、步进计时器、模型调用都在 node 半边，
  浏览器半边只负责画和点。所以关掉页面再打开，小镇还在原来的步数上。
- **是**：一套**判定先行**的规则。凡是有失败可能的行动，先掷 1 枚 D6 再叙事；
  骰值来自引擎，模型不能自己宣布成败。
- **不是**：聊天窗口的装饰。它是一条双面 bundle 插件行，和 `dsh-better-sidebar`
  自带的 8 个 tab 走同一套 `ctx.betterSidebar` 注册 API。

## 安装

```sh
# 从仓库根目录
bash scripts/install.sh                       # 默认装进 ~/.dsh/profiles/web
bash scripts/install.sh /path/to/profile      # 或指定 profile
```

脚本会：构建 `lib/`（build.mjs 内含 `tsc --noEmit` 类型门禁）→ 往 profile 的
`dependencies` 写 `link:<本仓库>` → 把 `dsh-paranim` 追加进 `dsh.profile.bundles` →
跑 `pnpm install`。

**必须重启 dsh web 进程**才会装载（客户端 bundle 需要重新加载）。
重启后在侧边栏「+」菜单里选「**他化自在天**」。

卸载：`bash scripts/uninstall.sh [profile-dir]`（沙盒数据默认保留）。

## 界面

页签分四页，底部常驻步进控制与指令输入框。

**世界** — 小镇地图、在场者清单、最近发生的事。

地图用**真实像素图集**绘制（Kenney，全部 CC0 1.0，16×16）：

| 图集 | 网格 | 分工 |
| --- | --- | --- |
| Tiny Town | 12×11 | 主素材：地面、道路、屋顶、墙体、树 |
| Tiny Farm | 12×11 | 主素材：田垄、栅栏、农舍 |
| Tiny Battle | 18×11 | 主素材：载具、机械、道具 |
| Roguelike Modern City | 37×28 | 补充：镇上物件与设施 |
| 1-Bit Pack | 49×22 | **后备**：Tiny 系列缺的标记 / 状态 / 事件符号 |
| Roguelike Characters | 54×12 | 角色（16×16，多朝向） |

建筑不是单个大 sprite，而是**按占地逐格拼装**：屋顶横条 + 墙体横条 + 门窗。
原因很实际——原版 Smallville 的地标包围盒从 4×4 到 26×22 差异极大，
固定尺寸的 sprite 要么被拉伸变形、要么盖不满；模块化拼装才能适配任意 `w×h`。

**哪一类东西用图集里的哪几格，全在 `src/client/mapStyle.ts` 一个文件里**，
形状是「语义槽位 → 候选格列表（随机取一个）」。地面给 4 个候选是为了不做成棋盘；
`roofWarm` 只给 1 个是因为它本来就是"暖瓦这一套"；候选为空数组表示暂无素材，
渲染层**跳过而不是画错格子**——所以你可以先跑起来再逐格调。

### 序号为什么需要你核对

瓦片序号是"看着定的"，不是算出来的。一张 140×100 的地图由几十种瓦片拼成，
**错一格在浏览器里只表现为"有点怪"**，不报错、typecheck 也看不见。工具链为此做了三件事：

| 命令 | 用途 |
| --- | --- |
| `npm run assets:inspect <图集> [--rows A-B] [--at 列:行]` | 把图集压成色块打到终端逐格查看 |
| `npm run assets:normalize` | 原始图集 → 规范网格（消掉 1px 间隙） |
| `npm run assets:snapshot` | 规范网格 → `src/client/sheetData.ts`（base64 内嵌） |

"消间隙"这一步不是洁癖：各家图集的瓦片带 1px 间隙（步长 17 而非 16），而
`drawImage` 按像素矩形取图——间隙不处理，取出来的每格右下角都会拖着邻居一条边。

左键点地图上的角色即选中它；右键点建筑或物件打开状态编辑菜单。视图控制在地图左上角
（`−` / `×` / `+` / `1:1` / `铺满`）。

**智能体** — 需求 3 的编排面板：
- **数量**：「＋ 新增智能体」把沙盒里待入场的角色放进小镇（沙盒有 25 位候选名册时，
  点一次放一位）；也可以直接手填一个全新的居民。
- **身份与外貌**：姓名、身份、外貌、性格、来历。
- **目标**：它想要什么。这是驱动它做事的动机。
- **日程与随身**：计划（每行一条，每走一步消耗一条）、随身物品。

> 角色卡**刻意不设**"恐惧 / 隐瞒"这类内在心理字段。它们属于写小说时的人物小传，
> 放进可复用的角色卡会让每张卡都背上两个填空，并与 `性格` / `来历` / `想要` 的语义
> 互相覆盖；有所忌惮或有所隐瞒写进这三个既有字段即可，模型同样读得到。
> （早期版本曾带这两个字段，v0.2.1 已从 schema、界面与镜像数据中一并移除；
> 清理用 `node scripts/migrate-drop-fields.mjs fear secret`，只删键、其它内容原样保留。）
- **六维属性**：力量 STR / 体质 CON / 敏捷 DEX / 外貌 APP / 智力 INT / 意志 POW，
  常人区间 **4–10**（可越界，UI 会提示）。提供「设为平均 7」与「随机掷一版」。
- **驱动模型**：从 DSH 当前已注册的 provider/model 里选；留空表示跟随宿主默认模型。
  某个智能体的路由坏掉只会让它自己降级，不会拖着整座镇停摆。

**世界沙盒** — 需求 2 的沙盒库：
- 载入 / 另存为副本 / 新建空沙盒 / 删除；
- **保存当前沙盒**（`fromRun`：把此刻每个智能体的位置与设定固化回沙盒）；
- **重置推演**：保留沙盒设定，回到开局那天，并可选带几个智能体重新入场；
- **恢复出厂**：把 `smallville` 恢复成随插件发货的镜像；
- 物件库：一键把路灯「→ 设为故障 / → 修好」、开关 `open`/`lit`/`running` 之类布尔槽。

**事件流** — 每一件事，判定带骰面与难度（`D6=4 + DEX 7 = 11 ≥ 11 → 成功`）；
可按在场者过滤、可只看判定。页尾列出完整难度阶梯。

消息栏有**三种渲染模式**（底栏「消息」切换）：

| 模式 | 长什么样 | 适合 |
| --- | --- | --- |
| 卡片 | 类型标签 + 正文 + 判定块，每类一个圆角卡片 | 默认，信息最全 |
| 日志 | 单行等宽，色调只在左侧条与类型字上 | 快速扫读、复盘 |
| 对白 | 说话的行放大高亮，其余压成小注 | 看"谁在和谁说话" |

着色**按语义而不是按序号**：事件本来就分 kind（移动/对话/行动/改动/指令/入场/离场/系统），
判定还带成败与恒定成败；每一类有自己的前景色、左边条色与图标，所以"哪条是判定、
哪条是状态改动、哪条是你下的指令"一眼分得开。正文里的对话「…」、骰值 `D6=n`
与被引用的物件名也会各自换色。

### 主题

底栏「主题」可在**四套配色**间即时切换（只换变量表，布局与信息密度不动）：

| 主题 | 适用 |
| --- | --- |
| 黑曜石 | 深色工作台，地图最亮。默认 |
| 羊皮纸 | 暖色纸面，适合长时间读事件流 |
| 终端绿 | 单色磷光，冷峻 |
| 白昼 | 浅灰冷调，白背景下不刺眼 |

主题表在 `src/client/theme.ts` 里，**加一套主题 = 加一项数据**，不需要动任何组件：
所有组件都只取 `--pa-*` 变量，切主题只是换一份变量值。主题与消息模式存在浏览器
`localStorage`（纯外观偏好，与沙盒/运行态无关，写进服务端会让它随工作区漂移）。

### 右键改物体状态（需求 5）

在地图上**右键**任意地标或物件（例如街边那盏路灯），弹出的菜单里可以：

- 改任意状态槽——按它**原本的类型**给控件：`status` 是下拉（正常 / 故障 / 损坏 / 维修中 / 锁住 / 被人动过），
  布尔给「是/否」开关，数字给数字框；
- 加新状态键、清空某个键（置 `null` = 删除该键）；
- 改名、改坐标、从沙盒删除该物体。

改动立刻落盘，并写进事件流（含**谁改的**与时间戳）：

```
[第 7 步] 玩家把「咖啡馆门口的路灯」的 status「正常」→「故障」。   🔧
```

### 步进（需求 6）

- **手动步进**：按一下走一步，等它跑完（每个智能体一次模型调用，并发发起）。
- **自动步进**：开一个宿主侧计时器，按「时间流速」持续推世界。滑杆拉到最右是最快
  （2 秒一步，下限），最左是最慢（10 分钟一步）。
- 关掉页面自动步进**不会停**（计时器在宿主进程），插件被卸载/禁用时会被清掉。
- 每个智能体各自记忆上限 24 条 + 一条来历摘要，超长记忆会被裁剪，
  这样长跑不会把上下文撑爆、也不会让角色"忘记自己是谁"。

### 指令（需求 3 的指令引导）

底栏输入框选中一个智能体后写一句话（例如「去咖啡馆找阿比盖尔打听昨天夜里的事」），
回车即下达。它会在**下一次步进**时把这句话当作脑海里必须立刻执行的声音（优先级高于自己的计划），
执行完就消费掉，同时作为 `whisper` 留进记忆。指令本身也会进事件流（标记为 `📣`），
所以你事后能对上"哪一句话导致了哪一步"。

## 判定规则（需求 4）

```
掷 1 枚 D6，  骰值 + 对应属性  ≥  难度   →  成功
```

- **1 恒失败、6 恒成功**（各自附带额外代价 / 额外收益）。没有这条，一个 STR 10 的人
  对「严峻 17」永远只能靠 6 —— 骰子就不再是运气，而是唯一的通道；有了这条，
  6 仍是通道，但 1 让强者也会失手，剧情才有代价。
- **对抗**（擒抱 vs 挣脱、潜行 vs 侦查、谎言 vs 洞察）：双方各掷一次，比较
  「骰值 + 属性」，**平手判防守方收益**（攻方必须真正压过）。
  对抗里 1/6 **不**一票否决——否则"力气大的人更容易赢"这件事会被抹掉。
- 修正逐项登记（`{label, value}`），结论里写清来源，例如「手持手电 +1」。

难度阶梯（`difficultyId` → 目标数）：

| id | 档位 | 目标数 | 适合 |
| --- | --- | --- | --- |
| `trivial` | 随手 | 6 | 系鞋带、推门 |
| `easy` | 容易 | 9 | 搬一把椅子、认路 |
| `normal` | 常规 | 11 | 翻墙、套话（缺省） |
| `hard` | 棘手 | 13 | 徒手爬三楼、说服固执的店主 |
| `very-hard` | 艰难 | 15 | 众目下偷东西、徒手压制壮汉 |
| `brutal` | 严峻 | 17 | 暴雨里追踪、一句话扭转敌意 |
| `nearly-impossible` | 近乎不可能 | 19 | 只有 6 或满骰加极高属性才可能 |

引擎自己会掷的判定：**移动**（DEX，距离越远越难：>15 格常规 / >35 格棘手 / >60 格艰难）、
**动手改物体**（DEX，且必须在 4 格之内）、**取用物品**（DEX）、**脱身**（DEX）。
`check` / `opposed` / `attack` 由模型声明用哪一项属性与哪一档难度。

## 智能体每步在做什么

引擎每步向每个智能体要**一个声明式动作**：

```json
{
  "thought": "它此刻心里在想什么（进私有记忆，不进公共事件流）",
  "kind": "move | say | observe | act | take | give | check | opposed | attack | flee | wait",
  "text": "第三人称叙述（进公共事件流）",
  "placeId": "move 的目标地标 id",
  "targetAgentId": "对话/对抗的对象 id",
  "attr": "check/opposed/attack 用哪项属性",
  "difficultyId": "check 的难度档位",
  "mutations": [{ "objectId": "lamp-cafe", "key": "status", "value": "故障" }]
}
```

**为什么状态改动是显式声明的，而不是引擎事后比对快照**：猜出来的 diff 无法区分
"发生过某个动作"与"巧合地前后状态相同"，复盘会失真；显式声明让每一条状态变化
都能追到是谁、在哪一步、用什么权限做的。

降级路径（模型不可用 / 输出不是 JSON / 调用超时）**不会编造剧情**：只执行计划里的
下一步与眼前真正能做的事（走动、观察、跟旁边的人搭话、顺手摆弄够得到的物件）。
这样手动步进永远有反馈，不会看起来像坏了。

## 数据落在哪

```
${DSH_HOME:-~/.dsh}/dsh-paranim/
  sandboxes/<id>.json        世界沙盒（**设定**：地标/物件/角色模板/关系）
  runs/<工作区>/<id>.json     运行态（**这一局**：步数、坐标、记忆、事件流、指令）
  step/<工作区>.json          步进设置（手动/自动 + 时间流速）
```

沙盒与运行态分开放是刻意的：沙盒是设定，运行态是这一局。把记忆和坐标写回沙盒，
同一个小镇就没法用不同人数、不同角色再开一局了。**「保存当前沙盒」是唯一把它们
折到一起的通道**，而且要你显式点。

全部是明文 JSON，可以直接手改。读进来会走一遍归一化（缺失字段补齐、越界值夹紧、
脏坐标丢弃），所以手改坏了最坏情况是那一项被修正，而不是整个沙盒打不开。

随插件发货的镜像在 `assets/smallville.json`，首次启动时复制一份到 `sandboxes/`
成为**可编辑的**初始沙盒（`builtin: true` 只用来提示出处、禁止误删）。

## 模型工具

同一份数据的两条入口：界面点一次和模型调一次落到同一个 store 与引擎上，
不存在第二套状态。所有写操作都会记录"谁做的"（`by`），事件流里能区分
「玩家右键改的」与「模型改的」。

| 工具 | 用途 |
| --- | --- |
| `paranim_world` | 看现状：地标/物件状态、智能体六维与记忆、事件流 |
| `paranim_step` | 推进世界（可一次多步） |
| `paranim_direct` | 下达指令：一句话引导某个智能体 |
| `paranim_object` | 改物体状态 / 新增 / 移除物件 |
| `paranim_agent` | 增改智能体（外貌/性格/六维/驱动模型/计划）或让它离场 |
| `paranim_sandbox` | 沙盒列表 / 载入 / 另存 / 新建 / 把运行态导回设定 / 重置 |
| `paranim_models` | 查当前可用的驱动模型 |

另外会注册一段系统提示（`paranim` 段，order 120），把沙盒的存在、判定规则与
六维含义讲给模型，避免它靠猜。

## 开发

```sh
npm i
npm run check        # typecheck + 单元测试 + 端到端自检 + 构建
npm run typecheck
npm run test         # 判定引擎单测（规则/对抗/移动/状态护栏/动作清洗）
npm run selftest     # 离线端到端：store → 引擎 → 路由 → 工具，含假 llm 与假 req/res
npm run gen:fallback   # 改完 assets/smallville.json 后重新生成内联兜底小镇
npm run migrate:fields # 从镜像与所有沙盒副本里删掉指定字段（只删键，可先 --list 预览）
npm run preview:sprites # 把像素素材用真彩打到终端，校验行宽一致与调色板覆盖
npm run build
```

`src/host/fallback.ts` 是**生成物**（`scripts/gen-fallback.mjs` 从 `assets/smallville.json`
产出），不要手改：内联兜底是镜像读不到时的降级路径，两份数据必须一致，手写一份就等于
埋一个"改了一处忘了另一处、只在真正降级时才暴露"的漂移。

`src/host/selftest.ts` 是这个项目的主要防线：它用一个假的 `llm` 服务与假的
node `req/res` 把每条路由、每条降级路径、自动步进的计时器都真的跑一遍
（118 项断言，含"种入的沙盒与镜像逐字段一致"这种外部可核对的锚点）。插件的失败模式
大多不是类型错误，而是"沙盒没种上"、"某条护栏把正常请求也挡了"、"模型不可用时世界
停摆"——那些只有真的走一遍才会现形。

`build.mjs` 会在类型门禁之后**断言客户端 bundle 里真的含有关键 UI 片段**
（右键菜单、手动/自动步进、六维标签、恐惧/隐瞒字段等 16 项）：少写一段 JSX
不会被 tsc 发现，但会被这道断言拦下。

### 页签布局的硬约束（"向下无限下坠"的来历）

页签宿主是一个**有确定高度的块级滚动容器**，不是 flex 容器。所以本插件每一层
都必须自己钉死高度，缺一层就会退化成内容高度：

- `.pa-root` 要 `height: 100% + max-height: 100% + min-height: 0 + overflow: hidden`；
- 每一层 flex 子项（`.pa-body` / `.pa-mapwrap` / `.pa-side`）都要 `min-height: 0`
  —— flex 项的自动最小尺寸默认是"内容高度"，少了这一行，容器会被内容撑高；
- 画布必须是 `position: absolute; inset: 0`，尺寸**只由容器决定**。

前两条少了任一条，就会形成"容器被内容撑高 → ResizeObserver 量到更大的高度 →
画布跟着变高 → 内容再变高"的正反馈，表现就是页面向下无限生长。画布绝对定位是
把这条回路彻底切断：它不再参与父容器的尺寸计算。`MapCanvas` 里的 ResizeObserver
回调还额外做了"尺寸没变就返回同一个 state 引用"的短路，避免回调→渲染→回调的
第二条回路。

### 目录

```
src/shared/model.ts    属性、沙盒 schema、路由契约（两端共享的唯一契约）
src/shared/rules.ts    判定引擎与动作结算（纯函数，可脱离运行时单测）
src/host/engine.ts     一步的流程：并发取动作 → 串行结算 → 落记忆
src/host/store.ts      沙盒库 / 运行态 / 步进设置的持久化与归一化
src/host/routes.ts     /paranim/* 路由（含信任围栏与自动步进计时器）
src/host/tools.ts      模型工具与提示段
src/host/fallback.ts   内联兜底小镇（镜像缺失时的降级路径）
src/client/index.tsx  侧边栏页签四页（世界 / 智能体 / 世界沙盒 / 事件流）+ 步进控制
src/client/MapCanvas.tsx 画布组件：视图、命中判定、右键状态菜单
src/client/town.ts    小镇渲染层：地块 / 建筑 / 道路 / 角色（纯函数，可离线跑）
src/client/pixelart.ts 内联像素素材表：55 色调色板 + 地面/建筑/行走图/物件点阵
src/client/styles.ts  页签样式（深色工作台 + DSH 主题变量回退）
assets/                复刻镜像素材与出处索引
```

### 为什么它是宿主行，不是 preset

沙盒库、运行态与自动步进的消费者（页签、模型工具、计时器）都跨会话存活，
"这个小镇在跑"是宿主级的进程事实。本行**不发布任何服务**，所以不需要 `isolate` realm；
它只消费宿主已有的 `webServer` / `tools` / `systemPrompt` / `llm` / `agentDefaultModel` / `sessions`。
